# Changelog

All notable changes to Agentic Researcher are documented here.

## [Unreleased] — performance, latency, and retrieval wave (2026-09-03)

### Added
- **`web_search` results are cached beside fetched sources.** A search is remembered in `Agent Sources/search-cache.json` (newest 200 searches, fresh for the same 24 hours a fetched source is), keyed by the normalized query, the index it addressed, and the result count, so a follow-up mission that asks the same question makes no provider call. The tool result says `fromCache`/`cachedPath` exactly as `web_fetch` does; an explicit `refresh` or a freshness-sensitive mission ("latest", "current", "as of") bypasses it the same way; empty result sets are never cached. The file is written through the source cache's own serialized path, so it stays cache maintenance — never a note write or a mutation receipt.
- **The keyless academic search tier retries once and reports partial failures.** Each free provider request (Wikipedia, OpenAlex, arXiv, Crossref, PubMed, ClinicalTrials, CourtListener) now rides the shared transient-retry path (one retry on 429/5xx or a thrown transport failure; a 4xx is never retried), and a provider that still fails no longer disappears silently: the fusion continues with the providers that answered and the `web_search` result carries `providerFailures: [{ provider, code }]` (`http_<status>`, `invalid_response`, `transport_error`, `aborted`).
- **Opt-in real-web research quality lane.** `npm run test:e2e:research-real-web` (Playwright project `research-real-web`, scenario RESEARCH-WEB-01) runs two fixed cited-summary prompts — one STEM, one policy/economics — against the real provider `/web_search` and `/web_fetch` through the plugin's own transport, with no owned web backend. It asserts only what the product promises for a sourced mission (completion with one append receipt, at least two usable parsed sources from at least two domains, every cited passage bound to a fetched source, a limitations heading) and emits the mission scorecard like DU-02 so `npm run scorecards:harvest` can baseline it. It is measurement only: real API budget, non-deterministic, not part of the proof matrix, and its scorecard is a diagnostic until harvested.
- **"Fast" semantic tuning preset.** Settings → Semantic tuning gains Fast: `jinaai/jina-embeddings-v2-small-en` at 512 dimensions with 256-token chunks. On the embedder benchmark (`npm run bench:embedders`, i7-1165G7, CPU only) it indexed 31 chunks per second against the shipped model's 10.7 and scored 1.00 recall@1 and MRR on both the exact-term and paraphrase query sets, with the lowest query latency. Balanced stays the default because choosing a different model or chunking rebuilds an existing vault's index once.
- **Choose an embedding model and see what it costs.** The semantic embedding model row is a dropdown of the catalogue (id, tier, download size) with a custom-id escape hatch; the Test embedder button now also times sixteen note-sized documents and reports documents per second on this machine; and twenty seconds after startup, if semantic search is on but its runtime is not working, a notice says so instead of leaving the first sign to a mission's degraded-retrieval report.
- **Embedding model catalogue.** `src/embeddings/embeddingModelCatalogV1.ts` records, for every model FastEmbed can run on a CPU, its native width, whether it supports Matryoshka truncation, its input limit, size, and the instruction prefixes it was trained with (snowflake-arctic and mxbai now get their query-side instruction). The dimension setting accepts any width the model produces instead of only 256 or 512; a non-Matryoshka model is always indexed at its native width, and the Python helper applies the layer-norm/truncate/L2 recipe only to models that support it (every other model was silently being corrupted by it). The helper does the vector maths in numpy when available, reports `dim_mismatch` with the width it actually got, and records a provider id in the index so a runtime change rebuilds it exactly once. The settings row now offers the catalogue's models with their cost, and the dead one-shot `scripts/semantic_embed_fastembed.py` is gone.
- **Reset settings to defaults** (Settings → diagnostics section): a two-click warning button restores every preference to the shipped defaults while keeping providers, base URLs, API keys, chosen models, and connection proofs.
- **Startup timing.** The plugin measures onload to core-ready per phase and the layout-ready tasks that follow (retention sweep, durable-resume scan, template library, workspace cleanup), logs one line for each, exposes both through `getStartupTiming()`, and includes them in Export diagnostics; `npm run measure:startup-timing` measures it in the real Obsidian with a seeded Agent Runs backlog.

### Fixed
- **A clarifying question no longer erases a pending blocker or approval in Chat.** The chat attention banner was one slot that four renderers each emptied before drawing (readiness card, blocked-run card, approval prompt, clarifying question), so whichever arrived last destroyed the others and their buttons. The banner is now a stack of cards keyed by `data-attention-key` (readiness, blocked, approval, clarification, in that order): each renderer replaces only its own card, answering a question or resolving an approval removes only that card, a starting run clears the two pre-run gate cards, and run completion or Clear chat still clears everything. Cards are separated by a hairline; the clarification accent moves from the banner to its card. Every existing test id and class on the cards is unchanged.
- **Editing one note no longer disables the semantic index.** Any changed, deleted, or new note used to mark the whole index stale, so every `semantic_search_notes` call during a mission (the user is always editing something, and the agent appends to a note) silently fell back to the unindexed 300-note live path. Staleness is now per note: drifted notes are excluded from the indexed scan, up to three changed notes are embedded on the spot and merged into the ranking so the note being edited still turns up, and the result and its retrieval-coverage record name exactly which notes were excluded, merged, or not yet indexed. Only settings changes, disabled vectors, missing shards, or a majority-stale index (≥50 notes and ≥20%) still fail the indexed search; the report names at most 25 paths per category and always carries exact counts, so a vault past the index ceiling does not push thousands of paths into every result. The index manifest is also parsed once per file version rather than on every search.
- **Live semantic search batches its embeds and outranks a rebuild in progress.** The unindexed fallback used to send every chunk of up to 300 notes in one helper request (the shape behind `output_too_large` and 180 s timeouts); it now embeds the query in its own request and documents in batches of 64. The embedding provider's serial queue has two classes: a user-facing search or reflex classification is interactive and runs as soon as the in-flight request settles, ahead of any queued index-rebuild batch.
- **The reflex intent classifier embeds with the index's prefixes.** It used to embed its prototypes and the prompt bare while every indexed document carried the model's instruction prefix, comparing vectors from two input conventions; it now resolves the same prefix pair, effective dimension, and truncation rule the vault index uses.
- **A stopped or unloaded mission no longer waits for the embedding helper.** Disabling the plugin (or stopping a run) while the reflex intent classifier was waiting on the FastEmbed Python helper left the old run alive for up to three minutes: dispose settled the in-flight request, the helper's retry path read that as a crash and respawned a zombie helper, and the classifier had no abort race. The helper now refuses to respawn after dispose, the classifier races the run's abort signal and falls back deterministically (`run_aborted`), and every reflex evaluation receives the run's signal. The same rule now covers the other awaits a stopped run could hang on: a semantic search skips a queued embedding request and abandons an in-flight one the moment the run stops (falling back to lexical scoring), extension verifiers race the run's signal instead of only their 30 s timeout, and sandbox preparation forwards the signal to the provider probe.
- **A busy shared provider account no longer ends the mission after three quick retries.** Rate-limit errors (HTTP 429, "too many concurrent requests") now get their own retry budget: up to seven attempts with delays growing to 30 s (about 47 s of waiting, Retry-After honored), while other transient errors keep the general budget. The status line says the provider is rate limiting and how long the wait is.
- **"Do not write or edit any note" now also stops the host's research-memory auto-save.** The post-acceptance memory save ran after any accepted research answer regardless of an explicit refusal, leaving a receipt the user had ruled out; the planner's memory node and the save now read one shared refusal predicate, so a refused write is neither planned nor performed and the run still completes normally.

### Changed
- **Per-sub-question evidence minima follow the research effort tier.** Every research sub-question used to require exactly one evidence item regardless of depth. A plan now derives its minima from the tier it carries once that tier is selected: one usable fetched source per evidence-bearing web question at quick/standard, two at deep/extended (reserved per question inside the fetched-source contract, so an explicit "two sources" stays a closed two-source contract and the fetch ladder never owes more than the plan demands), one for every vault-side question at every tier (a search-plus-read gather must still complete), and zero for the host-appended limitations/confidence question, which now carries a structural `role: "limitations_confidence"` instead of being recognised by its wording. The distinct-domain floor rises from two to three at deep/extended, still bounded by the fetched-source count. Persisted plans resume verbatim; a utility-model effort verdict or an effort ceiling re-derives the minima with the tier it settles on.
- **Plugin load no longer reads every finished run note.** Each `Agent Runs/<runId>.md` now carries an `agentic_run_status` frontmatter property written in the same rewrite as its Runtime Snapshot, and the load-path scans read it through Obsidian's metadata cache, skipping terminal notes without a read (notes without the property, or not yet indexed, are still read). With the default retention of 200 terminal runs the immediate phase used to read and parse all of them on every launch.
- **The prompt prefix is byte-stable across agent steps.** The per-step segment budget line was folded into the stage system prompt with counts that changed every step, and the mission-plan block was re-rendered in place with the live active task, so every tool-loop request diverged inside its prefix and no provider prefix cache could reuse it. Both now ride one ephemeral system card inserted before the last message; the seeded plan block is a static marker block. The runner emits a per-step `prompt_prefix_reuse` metric, Run Details shows cached prompt tokens and the average reuse, and the eval CSV gains `model_calls`, `reported_tokens`, `cached_prompt_tokens`, and `prompt_prefix_reuse_avg` (blank when unknown). The run's usage aggregate (persisted in the ledger, projected by the run coordinator) now carries the prefix-reuse samples and their total, so continuations and the research lane read the measured average instead of a blank.
- **Fewer and cheaper model calls per mission.** Continuation segments skip the structured router whose verdict the resume branch discards. Writeback-class calls (streamed note drafts, the final answer stream, the word-count correction pass, the English repair pass) resolve thinking through the writeback role instead of the lead flag; the correction pass had silently ignored its thinking argument and run at provider default. OpenAI-compatible streams now request `stream_options.include_usage` so streamed calls report tokens, and `num_ctx` is no longer sent as `max_tokens`.
- **A dead model endpoint stops being re-dialled.** A session-scoped circuit breaker per provider/base URL/model opens after five consecutive provider-health failures, fails fast for a cooldown, and admits one probe; auth, rate limits, budget, policy refusals, and cancellations never trip it, and the specialist fallback still runs against its own endpoint.
- **Continuation segments keep the previous segment's web results** (successful `web_fetch`/`web_search` results and trusted hash-bound reads) instead of starting from an empty cache.
- **Plugin load and note switches do less disk work.** Startup hydration stops at the newest resumable run instead of reading every note under `Agent Runs/`; project memory and the run projection load in parallel; note switches reload memory through a 150 ms debounce gated on file mtimes, so an unchanged vault costs no reads per click.
- **Vault search ranks by corpus statistics.** `search_markdown_files` counts occurrences informatively (adjacent repeats collapse, keyword-list lines weigh a quarter), weights terms by BM25 IDF over the scanned notes, saturates and length-normalizes frequency, and rewards covering every term of a multi-term query. On the retrieval fixture recall@1 went from 0.00 to 1.00 and MRR from 0.50 to 1.00. No index is persisted.
- **Semantic search scores shards in place**: vectors are decoded once per shard version into a typed array and compared without per-row allocation (scores identical to six decimals); the shard cache is cleared on unload.
- **Append idempotency keys on the mission-graph node**, so a retried or resumed `append_to_current_file` under the same node is skipped exactly once instead of duplicating content; the step-scoped key remains the fallback for graphless runs.
- **The English-only output guard stands down for an English prompt that explicitly asks for Chinese, Japanese, or Korean output**, and the prompt-language predicate lives in one module instead of two private copies.
- **Tool results carrying external content** (`web_*`, `browser_*`, `github_*`, `linear_*`, `read_source_section`) open with a machine-readable `trust: "untrusted_external_content"` marker and a one-line guard before any content.
- **Run-note rewrites do less disk work.** The Runtime Snapshot fence is one compact JSON line (it was pretty-printed, roughly doubling the bytes of every write-ahead-log rewrite); the snapshot, ledger, and checkpoint writers pre-read the note through a stat-keyed cache of the last exact write instead of re-reading 40–200 KB before every splice (any external change to mtime or size forces a real read, and every write is still read back and compared); the persisted evidence projection is capped at 512 records, evicting sources that produced no usable content first. The ledger and the snapshot now land in one rewrite (every ledger persist used to be followed by a duplicate snapshot write), and the post-tool ledger persists (graph reconcile, reflex checkpoint, receipts, evidence-free or applied-mutation tool results) ride the next write-ahead-log transition or the flush before the next model call instead of forcing rewrites of their own. On a scripted search → read → append run the run note was rewritten 11 times instead of 34; an evidence-bearing read tool costs one rewrite (was four) and a mutation four (was twelve).
- **Disk time is named in the wall-clock line.** Durable run-note writes, mission-graph patch transactions, and prompt compaction are attributed as `host_work` metrics, and the Run Details wall-clock line appends `host work …` with a per-phase split when anything was attributed.
- **The Agent Runs retention sweep no longer reads every run note at layout-ready.** It counts notes older than the retention cutoff first and reads nothing when none can be pruned (an active vault of recent runs), reads only the aged notes otherwise, prefers the cache-backed read, and yields between batches.
- **Research planning asks the utility model two questions at once.** The starting-effort assist and the subquestion assist depend only on the deterministic plan, so they run concurrently instead of back to back; the effort verdict is still applied first and an explicit closed source set still skips the subquestion assist.
- **Developer latency:** the unit runner drops its undocumented `--test-concurrency=1` pin (bounded parallelism) and the post-test dashboard skips regeneration when nothing changed; together with the run-note persistence work below, the full suite fell from 7.9 min to about 1.5–3 min wall clock (4,507 tests; the runner-heavy tests were dominated by run-note persist cost). README states the real minimum Obsidian version (1.11.4).


### Removed
- **The dead chat-side activity mirror.** `AgentView` still carried a `liveWorkstreamEl` "live workstream" strip and a `chatTeamStripEl` team strip that were never created (both were only ever assigned `null`), so every `appendWorkstreamLine` call returned at its guard and `renderChatTeamStrip` was unreachable; the fields, both renderers, their call sites, the `.agentic-researcher-live-workstream*` CSS, and the demo-recording probe that waited on `.agentic-researcher-live-workstream-line` are gone. Chat activity is summarized by the live-run card; the full status and tool streams stay in Run Details.

## [0.4.0] — unified desktop plugin

Desktop-only unified Agentic Researcher (`package.json` / `manifest.json` 0.4.0).

**Proof record (2026-07-28):** the exact live BYOK autonomous journey (`npm run test:e2e:byok-autonomous-journey`) is green end to end with its independent verifier: research with 4 host-verified sources → accepted note → Linear issue → validated code in a trusted repository workspace → exact-SHA verified commit `fa32638` → private GitHub draft PR → 69-word human reflection → IDE-openable Desktop export whose own tests pass — with GitHub, vault-backup, and workspace-metadata cleanup independently read back as clean. Model: `deepseek-v4-pro:cloud`. Known limitation: cheaper models (`minimax-m3`, `deepseek-v4-flash`) execute every individual stage but fail the composed journey on quality variance (thin research summaries, unrepairable first-draft code, post-hiccup tool wandering); the lane is model-quality-bound, not product-bound.

### Fixed
- **A mission that orders N writes to ONE note now gets N graph nodes.** The host planner deduplicated every effectful tool by NAME (`seenEffectfulPlannedNames`), so "append exactly one line containing MARKER_A1 … then append exactly one separate line containing MARKER_B2" — two ordered appends to a single note — planned ONE `append_to_current_file` node. A node's completion contract closes at its first receipt, so that node paid marker one and the frontier then had nothing to offer for marker two; acceptance now catches this honestly, but failing honestly is not passing. `deriveRepeatedOperationNodesV1` (`src/agent/repeatedOperationTargets.ts`) is the single seat the planner consumes, and it now answers both geometries of the same defect: two or more distinct DESTINATIONS the request names, and two or more ordered WRITES the request orders to one of them. The ordered-write count is not re-derived — it is `getRequiredLiteralAnchorsMissingFromTextV1`, the same authority acceptance uses, called against an EMPTY artifact so it yields every anchor the contract owes (passing `null` returns `[]` by design and would silently plan one node again). Over-provisioning is guarded four ways, because a node nothing can pay is as bad as too few: an explicit separation/ordering marker must be present; the writes must provably share one destination (caught a real regression where two appends to two different notes both resolved to the FIRST note's selector); every marker must sit in its own clause that itself carries the append verb, since "a line containing A and a line containing B" is satisfiable by one write; and the clauses must account for every owed marker, so the plan owes exactly what acceptance will demand. Only appends expand — a second `replace_*` would erase what the first wrote and a second `create_file` is unpayable by construction — and each node keeps the note as its destination rather than its marker, or the exact-path guard would refuse the very calls the nodes exist to admit. Single-write missions, ordering vocabulary included, keep byte-identical plans, and a sourced writeback that commits all of its literals in one write at finalization gains no extra turn.
- **A multi-marker write contract is no longer discharged by a single receipt.** `requiredTools` is a set, so `append_to_current_file` appears once however many ordered appends a mission demands, and `write_receipt` is satisfied by the presence of a receipt rather than by the count of work — so a two-marker mission that paid one append passed acceptance with `required_evidence_and_receipts_present` while its second marker had never been written. Acceptance now reads the artifact, which is the only count-aware evidence available, and names each required literal still missing from the current note (`literal:<marker>`). Scoped to missions that have already paid a current-note write, because this catches a HALF-paid contract rather than pre-empting an unwritten one; it fails open on an unreadable note, and the same shared helper now answers "how much of this write contract is still owed" for the resume heal too.
- **An unfilled placeholder tool name no longer costs a whole step.** Cheap models sometimes emit a literal function-calling template as the tool name — `$TOOL_NAME`, `${toolName}`, `<tool_name>`, `{{tool}}` — mid-ladder, when they compose the next call from remembered form instead of the offered schema (seen live right after a successful `read_template`). That is a formatting failure, not a request for an unavailable tool, but it spent a full model step on an unknown-tool refusal. When the offered frontier is exactly one **read-effect** tool, the call is now retried as that tool with its arguments untouched. Deliberately narrow, in the shape of the existing append-alias remap: ambiguity is never guessed (two or more offered tools fall through to the refusal, whose copy already names the exact next tool), and a mutation is never invented from a placeholder.
- **A receipt-proven durable write no longer has to be recited in the chat answer.** `final_relevance` demanded every user-required literal marker verbatim in the final output, so a mission that paid its append — receipt recorded, note verified, every write proof satisfied — still failed acceptance because its completion summary did not quote the marker. Acceptance never reached pass, so the run kept continuing until the production no-progress circuit stopped it. A marker's home is the note it landed in: once a write receipt proves that, the answer owes topical relevance, not recitation. Missions with no write proof are unchanged, and topical relevance still governs in both cases.
- **A continuation no longer adopts a restored mission graph that cannot authorize the work it owes.** A crash can persist a tool-less `final` stub whose capability envelope never granted `append_to_current_file` — the segment that planted it planned no write node, so no grant was minted. Adopting that record made the mission's required write structurally impossible: the resume heal cannot splice a node the envelope does not authorize, the empty-frontier fallback still offered the tool, and the graph authority refused every call until the budget died. The graph was unhealable *by construction*, which is why a chain of individually correct fixes to its consumers each produced a failure one stage deeper. Resume now refuses to adopt an unpaid final-only stub whose envelope lacks the grant for the mission's required current-note write, traces the refusal with the node ids, envelope tool names, and required write tools, and falls through to the existing fresh-plan path — which mints a real write node and a matching grant. The replan persists under the segment's own canonical graph id (a fresh envelope can never match the stub's fingerprint, which `MissionGraphSession.open` compares), and the stub is left on disk as forensic residue. Graphs with real nodes, and graphs whose required mutation is already paid, resume verbatim as before.
- **A mission's own write contract no longer levies passage-citation debt it can never pay.** `shouldRequireClaimGrounding`'s bare `\bverify\b` matched an ordered write contract ("append exactly one line containing X **and verify that write**"), so a mission that gathers no sources was required to cite persisted passage ids that cannot exist: the final answer was blocked with "Ground each material claim with a persisted passage citation", the run ended `budget`/`blocked` instead of `final`, and every continuation repeated it. `stripWriteVerificationPhrasesV1` removes write/edit/save/receipt-verification phrasings before the trigger runs, and the reflex evaluator's web-evidence trigger consumes the same exported predicate so both seats answer identically. A mixed prompt ("append a **cited** summary … and verify that write") still requires grounding. This was the third seat in 24 hours to arm a lexical trigger against a prompt's own forswearing or contract language, so `claimLedger.ts` now carries a **strip-then-test guard rule** for anyone adding such a trigger: strip negated and self-referential phrasings first, pin a truth table including a mixed case, and export the strip so no seat re-derives it. The rule also names the sibling defect family it belongs to — **self-detection**, where a detector matches a pattern against text that necessarily contains it, or a readiness probe accepts a signal that can appear mid-operation — with its own cure: exclude self from the scan, and pick a completion signal that cannot exist before completion.
- **The reflex completion gate no longer demands research a mission explicitly forswears, and can no longer terminal-fail an acceptance-passing run.** The negation-blind lexical triggers read "This task needs no web, memory, or vault research" as demands (`\bweb\b`, `\bvault\b`; an ordered write contract's "verify that write" matches `\bverify\b`), so a resumed segment whose durable work was fully paid burned every remaining step in completion corrections and was then classified `error` at the step cap — mission acceptance passing the whole time. `missionForswearsResearchEvidence` makes the triggers negation-aware, the terminal reflex arm defers to passing mission acceptance (one acceptance evaluation at that seat only), and the loop's final-synthesis shortcut also arms on a fully-terminal restored graph (final complete is not the final-only-remains ready/queued shape).
- **A continuation that resumes a crash-persisted final-only graph now heals it and pays the owed appends — exactly once each — instead of burning its budget.** Interrupted-continuation deadlock (two-subsystems instance #16): the restored stub graph — a ready, tool-less `final` with zero receipts — made `missionGraphOnlyFinalSynthesisRemainsV1` vacuously true, so the loop forced tool-less final synthesis while the empty-frontier fallback still offered `append_to_current_file` and the graph authority rejected all seven calls. One shared predicate (`missionGraphFinalOnlyStubOwesRequiredWorkV1`: final-only shape AND no completed required node carrying real receipts/evidence) now governs all three seats — the loop's "graph outranks segment accounting" shortcut, the resume splice heal (no longer gated on streamed-writeback context, which a streaming-off, pre-checkpoint kill never has), and the empty-frontier fallback. `graphHasCompletedRequiredMutation` additionally requires the completed node to carry proof, and the legacy plan projection no longer elects the tool-less `final` as the active task while real tool work shares its status tier (that election let the plan dependency gate defer the very write the healed graph authorized). The heal splices ONE node per required literal marker still missing from the live note — a node's completion contract closes at its first receipt, so a single node could never carry a multi-append mission across segments — which also serves the between-writes interruption (first marker landed with its receipt; only the remainder is spliced, behind an explicit content-verified declaration that the session's over-splicing guard demands) and refuses to splice at all when every marker already landed. The duplication flip side is closed at the write contract: an append that only repeats markers the note already contains, while another required marker is missing, is redirected to the missing one, and the write mission cannot close while spliced owed-write nodes remain open. Authority refusals are also classified from their real reason now (`invalid_state`, not a blanket `unknown_tool` from a hardcoded stand-in), and the frontier module's four privately re-inlined lifecycle/frontier selectors were collapsed onto the shared `missionGraphSelectors` authorities.
- **A paraphrased seed-bound research field can no longer strand a compound publish node.** While a durable project idea seed exists, its seed-bound accepted-research fields (the drift guard's own list: title, problemImpact, objective, proposedWork, nonGoals, acceptanceCriteria, evidence identity, riskClass) have exactly one admissible value each, so the host now substitutes the seeded values for a model paraphrase at the `publish_research_to_linear` execution boundary — journaled on the run trace — and again inside the tool's argument parsing for non-runner callers (one shared predicate, `canonicalSeedExactAcceptedResearchPackageV1`, the publish-seat mirror of `canonicalExactLinearIssueReadIdV1`), with the drift guard and the post-publish verifier/readback unchanged so packages without seed authority — and genuine corruption — still fail closed. Previously a paraphrased objective/proposedWork echo blocked the node with `tool_failure_repeated` despite corrective copy carrying the exact strings.
- **A mistranscribed Linear issue id can no longer strand an implementation mission.** When the mission names one exact issue and its verified contract read is still unsatisfied, the host substitutes the mission-named identity for a divergent model-echoed `linear_get_issue` id at the execution boundary (`canonicalExactLinearIssueReadIdV1`), with the existing post-read identity verifier unchanged. Previously a fumbled UUID 404-looped the node until the mission blocked.
- **Planner destinations are system-scoped.** The current-note selector fallback ran for every planned step, so all workspace and GitHub nodes in an issue-implementation mission were authored with the initiating note's `.md` path as their exact destination — making `code_workspace_create_file` unsatisfiable the moment the durable-workspace guard could enforce it. The fallback now applies only to vault-system tools; other systems keep `prompt-scoped-<system>-target` or an explicitly named step selector.
- **A completed graph now closes instead of dying on loop accounting.** Two coupled defects: after a resume, the segment-local expected-tool ledger started empty even though the durable graph had proven every node (`missionGraphOnlyFinalSynthesisRemainsV1` now makes the graph authoritative), and the repeated-call budget stop outranked the force-final branch, so a mission with a complete graph and paid delivery died wandering instead of writing its final synthesis. Satisfied required proofs now steer repetition into `force_final_no_tools`.
- **Linear's inline strong-emphasis rewrite no longer blocks idempotent issue adoption.** The provider serializes `__init__` as `**init**`; the reconciliation comparator treated the rewrite as content drift, so a created-then-adopted issue could never reconcile. Both sides now canonicalize inline strong emphasis before diffing, alongside the existing whole-line emphasis rule; genuine token differences still fail closed.
- The BYOK journey harness gained three exactness-preserving fixes of its own: the Phase B run-id read polls instead of racing the durable record; the mutation-authority audit accepts the three real approval-traceability links (identical fingerprints, the `linear-publication-<approvalId>` grant lineage of composite creates, and the content-bound `research-publication:<workItemFingerprint>` idempotency key of replays); and the audit failure message now prints the receipt and every candidate approval so a mismatch is diagnosable from artifacts alone.
- **A provisioned sandbox now actually reaches the plugin.** Host provisioning (`npm run setup:sandbox:wsl2`) records the immutable runtime's non-secret identity in the user environment, but only the settings modal could ever populate `sandbox.providerConfigs`. A fully provisioned machine therefore held zero providers, and every generated-code mission — including a bare "create a CLI checkers game in Python on my desktop" — stopped at `tool-04-code_validate_fast` with "No sandbox provider has passed its boundary probe." The Code runtime now adopts that host-provisioned binding at load, refreshes it when the runtime is re-provisioned under a new digest, and proves its boundary once per session. The probe remains the only authority for execution availability; the environment only nominates a candidate provider.
- Single-stage code delivery is gated at submit on the same sandbox proof as a compound run, so an unavailable sandbox is reported with a one-click next action instead of stranding a half-authored workspace mid-mission.
- Scratch code delivery no longer plans repository-only steps. `code_repair_record_cycle` resolves a trusted repository worktree and fails closed with `trusted_repository_required` anywhere else, so planning it for "write a checkers game on my desktop" put an unsatisfiable node mid-ladder: the workspace and files were authored, then the mission stopped with nothing delivered. Repository missions keep the full repair-and-commit ladder.
- The completion summary names the verified delivery path. A run that exported a real game to the Desktop used to end with "Done. 6 write operations completed." — the user was never told where it landed.
- Delivered folders are named after the request. Only the number-guessing e2e prompt had a real label; everything else landed on the Desktop as `code-deliverable-<hex>`. A checkers request now delivers `cli-checkers-game-<run>`, and the label is sanitized to a bounded `[a-z0-9-]` path segment.
- The delivery announcement names the artifact for every request, not just the one hardcoded prompt ("## Done — Code delivered" for everything else).
- A blocked run states the blocker in chat. It used to say "Blocked — open Run Details for the blocker" and save that uninformative line into conversation history, so the reason was lost from the transcript.
- **Orchestrator coding missions no longer leak a temp directory per run.** `GitWorktreeManager` lazily created one `agentic-researcher-disabled-hooks-*` directory under the OS temp root to neutralize git hooks and never removed it; 1,559 had accumulated on the development host. It now has an idempotent, best-effort `dispose()` that only ever removes a directly-owned directory carrying that exact prefix, called from the mission's `finally`. The unit suite was the dominant producer — it created managers without disposing them and leaked three per `npm test` run — so `tests/gitWorktreeManager.test.ts` now disposes every manager it creates.
- `npm run cleanup:e2e-runtime-residue` replaces the old daily-use cleanup, which matched a single `du03-live-*` prefix and therefore left every other lane's residue behind. It is a dry run by default, covers workspace metadata, repository worktrees, and temp directories, and reports anything ambiguous instead of deleting it.
- "save …" and "generate …" now count as code-deliverable phrasings, and `generate`/`make`/`build` count as known-folder export phrasings. "save a tic tac toe game in Python to my Documents folder" previously routed to no code tools at all, and "generate a python snake game on my desktop" planned the whole authoring ladder but no export.

- **Published Linear issues are assigned to you.** Discovery already recorded the connected viewer in `linearCapabilitySnapshot.viewer`, but `ResearchTicketPublisher.publish()` built its `linear_create_issue` payload with team, project, title, and description and no assignee — so every issue the agent filed landed unowned. It now defaults to the discovered viewer, keeps an explicit assignee authoritative, fails open to unassigned if resolution throws, and can be turned off with `linearAssignPublishedIssuesToViewer`.
- **A fine-grained GitHub PAT no longer blocks cleanup missions.** `githubCleanupAuthorityFromScopesV1` inferred delete authority from scope strings, but GitHub only returns `X-OAuth-Scopes` for classic tokens; a fine-grained PAT correctly reports none, which the gate read as "not authorized" and used to fail closed on every cleanup-stage mission. Authority is now reported as unknown for that credential kind and settled by the actual attempt, while an observable classic token that genuinely lacks `delete_repo` still fails closed.
- **The e2e harness can no longer report a skipped lane as a pass.** `run-e2e-exclusive.mjs` now reads a Playwright JSON report and fails when any selected project executed no non-skipped test — the exact shape that let `test:e2e:journeys` report success while its comma-joined `E2E_PLAYWRIGHT_LANE` made exact-equality guards skip themselves. That script is deleted, lane guards share a tolerant `laneSelectedV1`, and specs matched by two projects carry guards so they cannot run twice.
- **A passing run now leaves machine-readable proof.** `dailyUseReporter` only recorded `DU-0X`-titled tests, `daily-use` projects, and failures, so the flagship lane wrote no `daily-use-run-summary.json` at all — which also made the `ci.yml` job wired to `--lanes=desktop` fail on a passing run. The scorecard gate no longer returns a silent skip for lanes absent from the baseline; missing baselines are proof debt, with an explicit exemption set for lanes that make no model calls.
- `compound-flow-real-live` no longer falls back to a hard-coded Linear team UUID; it requires `LINEAR_LIVE_TEST_TEAM_ID` and asserts the id belongs to the connected workspace before mutating anything.

### Removed
- **The deterministic mock-model Playwright matrix.** Those lanes injected the sandbox provider configuration the product never adopted, so they stayed green on a host where a basic request could not complete — precisely the failure they existed to catch. Every remaining lane drives the installed plugin inside real Obsidian against a real model, a real external service, or both; `--mock-ai` is now refused with an explicit error. A new `desktop-checkers-delivery-real-live` lane replays the exact reported prompt from the exact reported state (zero configured providers), then compiles and runs the delivered game.

### Added
- Editor **Research selection (web)** command and context-menu action: highlight text → side-panel web research → proof-gated streamed/append writeback onto the current note. Optional **Research selection (chat only)** keeps the answer in chat.
- Host final-node verifier (`host-acceptance-v1`) records verification before MissionGraph final completion.
- Continue Latest Run surfaces the ledger/acceptance next action when a run is resumable.

### Changed
- Research-shaped note output treats `research` / `investigate` / cited findings language as content-producing (stream append by default when Chat only is off).
- Evidence conflict detection requires three shared claim terms (fewer false-positive stalls).
- Auto section follow-ups stop once source proof debt is cleared and cap at one section advance per fetch.
- Legacy MissionGraph evidence projection no longer invents vault proof from bare `web_search` / unknown tool-result kinds.
- Bare “latest/current …” language no longer forces web proof debt without an explicit research/web/source cue.

### Known limits
- The automatic Linear queue runs only while Obsidian is open and requires gate 5, a current read-only connection test, complete lifecycle mappings, and an unexpired user-issued grant.
- Automatic Linear `research` ticket execution remains web-read-only and chat-only; automatic vault writes from the queue stay blocked until a trusted vault executor/binding exists.
- GitHub publication (push / draft PR / merge) is available through the Integrations catalog and prepared-action path when configured; treat live provider proof as environment-gated.
- Overnight / long multi-segment runs are not background daemons (Obsidian must stay open for vault work).
- Real-AI soak outcome must be recorded before claiming Product 10 B3.
- Generated-code sandbox execution stays disabled until a Docker/Podman/WSL2/bubblewrap provider passes the boundary probe. Adoption of a host-provisioned binding removes the manual configuration step, not the probe.
